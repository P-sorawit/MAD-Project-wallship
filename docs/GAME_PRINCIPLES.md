# หลักการเกม Wallship / Battle Ship (ไม่ผูกกับฮาร์ดแวร์)

เอกสารนี้อธิบาย "เกมทำงานอย่างไร" แยกจาก "รันบนอะไร"
ใช้เป็นแบบเมื่อต้องวางระบบใหม่ (เปลี่ยนบอร์ด เปลี่ยนจอ หรือเขียนใหม่ในภาษาอื่น)
ตัวเลขทุกตัวตรงกับโค้ดปัจจุบันใน `core/` และ `firmware/3_game/`

## 1. องค์ประกอบของเกม

### 1.1 กระดาน
- ตาราง **8 คอลัมน์ × 7 แถว = 56 ช่อง**
- พิกัด `(x, y)`: `x = 0..7` (A–H), `y = 0..6` (แถว 1–7), `(0,0)` = มุมซ้ายบน = A1
- ผู้เล่นแต่ละคนมี 2 กระดาน:
  - **กระดานเรือ** — เรือของตัวเอง + ร่องรอยที่ถูกศัตรูยิง
  - **กระดานโจมตี** — ผลที่ตัวเองยิงใส่ศัตรู (ไม่เห็นเรือศัตรูจนจบเกม)

### 1.2 กองเรือ (ต่อผู้เล่น)
| ขนาด | จำนวน |
|---|---|
| ยาว 3 | 2 ลำ |
| ยาว 2 | 2 ลำ |
| ยาว 1 | 2 ลำ |
| **รวม** | **6 ลำ, 12 ช่อง (21% ของกระดาน)** |

- เรือเป็นเส้นตรง แนวนอนหรือแนวตั้ง
- **วางชิดกันได้** (รวมถึงชิดแนวทแยงและชิดข้าง) แต่ **ห้ามทับ**
- ห้ามล้นขอบกระดาน

### 1.3 ผู้เล่น
- 2 ฝั่ง: P1 และ P2
- **โหมด 2 คน**: คนทั้งคู่
- **โหมด 1 คน**: P1 = คน, P2 = AI

## 2. ข้อมูลที่ระบบต้องเก็บ (Data model)

### 2.1 ต่อผู้เล่น
```
own_board[7][8]   : 0 = น้ำ, 1..6 = หมายเลขเรือที่อยู่ช่องนั้น
shot_board[7][8]  : 0 = ยังไม่ถูกยิง, 1 = ถูกยิงแล้ว   (ช่องบนกระดาน "ของฉัน" ที่ศัตรูยิงมา)
ships[6]          : { id, length, hp, start_x, start_y, orientation, sunk }
```
- `hp` เริ่มเท่ากับ `length` ลดทีละ 1 เมื่อโดน, `hp = 0` ⇒ `sunk = true`
- **สถานะทุกช่องที่จะแสดงผล คำนวณได้จาก 2 ตารางนี้** ไม่ต้องเก็บสีแยก:

| own_board | shot_board | ship.sunk | ผล |
|---|---|---|---|
| 0 | 0 | – | น้ำ |
| 0 | 1 | – | ยิงพลาด |
| ≠0 | 0 | – | เรือ (ซ่อนจากศัตรู) |
| ≠0 | 1 | false | โดน |
| ≠0 | 1 | true | จม |

### 2.2 ของเกม
```
state           : S1..S6
mode            : 1P / 2P
current_player  : 0 / 1         (ใครถึงตายิง)
first_player    : 0 / 1
ready[2]        : วางเรือเสร็จและกดยืนยันแล้ว
placing[2]      : สถานะการวางเรือของแต่ละฝั่ง (ข้อ 4)
last_shot       : { shooter, x, y, result, sunk_length }   (ไว้แสดงผล)
winner, surrendered
timers          : เวลาเข้าสถานะ, เวลายิงนัดถัดไปของ AI
rng_state       : ตัวสุ่ม
```

## 3. ลำดับเกม (State machine)

```
        ┌──────────── 1s ─────────────┐
        ▼                              │
 S1 เลือกโหมด ──START──► S2 วางเรือ ──ทุกคน CONFIRM──► S3 เริ่มเกม ──2s──► S4 ต่อสู้
                                                          │                  │
                                                          └──ยอมแพ้──┐       │ จมครบ 6 / ยอมแพ้
                                                                     ▼       ▼
                                                    S6 รีเซ็ต ◄──NEW GAME── S5 แพ้-ชนะ
```

| State | ทำอะไร | ออกเมื่อ |
|---|---|---|
| **S1 เลือกโหมด** | P1 เลือก 1P/2P (เลือกเปลี่ยนไปมาได้) | P1 กด START |
| **S2 วางเรือ** | ทุกฝั่งที่เป็นคนวางเรือพร้อมกัน; AI วางสุ่มทันทีและถือว่า ready | `ready[0] && ready[1]` |
| **S3 เริ่มเกม** | สุ่มคนยิงก่อน, แสดงผลให้รู้ | ครบ 2 วินาที (หรือยอมแพ้) |
| **S4 ต่อสู้** | ผลัดกันยิง | เรือฝั่งใดจมครบ 6 ลำ หรือมีคนยอมแพ้ |
| **S5 แพ้-ชนะ** | ประกาศผล + เปิดเผยเรือทุกลำ | คนกด NEW GAME |
| **S6 รีเซ็ต** | ล้างทุกอย่างทั้งสองฝั่ง | ครบ 1 วินาที → S1 |

หลักสำคัญ: **มีที่เดียวที่เปลี่ยน state** (ตัวเกมหลัก) — ส่วนแสดงผลแค่อ่าน state ไปวาด

## 4. การวางเรือ (S2)

### 4.1 ขั้นตอนของผู้เล่น
1. เลือกความยาวเรือ (1/2/3) — เลือกได้เฉพาะขนาดที่ยังเหลือ
2. กดช่องบนกระดานเรือทีละช่องจนครบความยาว
3. ครบลำ → บันทึกลงกระดาน, ลดจำนวนเหลือของขนาดนั้น
4. ทำซ้ำจนครบ 6 ลำ → กด CONFIRM

### 4.2 กติกาตรวจทุกครั้งที่กดช่อง
ให้ `pending` = ช่องที่กดไปแล้วของลำที่กำลังวาง (เรียงจากต่ำไปสูง), `dir` = ทิศที่ล็อก

| ลำดับช่อง | เงื่อนไขที่ต้องผ่าน |
|---|---|
| ทุกช่อง | อยู่ในกระดาน, ไม่มีเรือลำอื่น, ไม่ซ้ำกับ pending |
| ช่องที่ 1 | – (เป็นจุดเริ่ม) |
| ช่องที่ 2 | ติดกับช่องที่ 1 แบบ **บน/ล่าง/ซ้าย/ขวา** (ไม่ทแยง) → **ล็อกทิศ** แนวนอนหรือแนวตั้ง |
| ช่องที่ 3 | ต้องอยู่ **ต่อปลายใดปลายหนึ่ง** ของ pending ในทิศที่ล็อก (กันรูปตัว L) |

ผิดเงื่อนไข → ปฏิเสธ (เสียง error) และไม่เปลี่ยนอะไร

```
press(x, y):
    if length ยังไม่เลือก              → NO_LENGTH
    if นอกกระดาน or มีเรือ or อยู่ใน pending → REJECT
    if pending ว่าง:  start = (x,y)
    elif มี 1 ช่อง:   ต้องห่าง start 1 ช่องแนวตรง → dir = ทิศนั้น, start = ช่องที่น้อยกว่า
    else:            ต้องเป็น start - dir  (ต่อหัว → start = ช่องนี้)
                      หรือ start + dir*count (ต่อท้าย)  ไม่งั้น REJECT
    count += 1
    if count == length: เขียนเรือลง own_board → SHIP_DONE
    else: PENDING
```

### 4.3 กติกาเสริม
- **เปลี่ยนความยาวกลางคัน** → ทิ้ง pending ของลำนั้น
- **วางครบลำแล้ว** ถ้ายังเหลือขนาดเดิม ให้คงการเลือกไว้ (สะดวก)
- **CANCEL** → ล้าง**ทั้งกระดาน**ของฝั่งนั้น เริ่มใหม่
- **CONFIRM** → ได้เฉพาะเมื่อครบ 6 ลำ, หลังกดแล้วฝั่งนั้นแก้ไม่ได้ (รออีกฝั่ง)
- ก่อนเข้า S3 ตรวจซ้ำว่ากองเรือถูกต้อง (จำนวนช่องตรง, ไม่ล้น, hp เต็ม)

### 4.4 การวางเรือแบบสุ่ม (AI)
```
repeat สูงสุด 10 รอบ:
    ล้างกระดาน
    for เรือ 6 ลำ (เรียงจากยาวไปสั้น 3,3,2,2,1,1):
        สุ่ม (x, y, แนว) สูงสุด 100 ครั้ง จนกว่าจะวางได้ (ไม่ล้น ไม่ทับ)
    ถ้าครบ 6 ลำ → สำเร็จ
ล้มเหลว (แทบเป็นไปไม่ได้ที่ 12/56 ช่อง)
```
วางลำยาวก่อน เพราะลำยาวหาที่ยากกว่า

## 5. การยิง (S4)

### 5.1 ตัดสินผลการยิง
```
shoot(shooter, x, y):
    defender = อีกฝั่ง
    if เกมจบแล้ว or shooter ไม่ใช่คนที่ถึงตา        → INVALID (ไม่เปลี่ยนอะไร)
    if นอกกระดาน or defender.shot_board[y][x] == 1  → INVALID (ยิงซ้ำ ไม่เสียตา)
    defender.shot_board[y][x] = 1
    id = defender.own_board[y][x]
    if id == 0:                      result = MISS
    else:
        ship = defender.ships[id]; ship.hp -= 1
        if ship.hp == 0: ship.sunk = true; result = SUNK (แจ้งความยาวเรือที่จม)
        else:            result = HIT
    if result == SUNK and เรือ defender จมครบ 6 ลำ: winner = shooter → จบเกม
    elif result == MISS: สลับตา
    # HIT / SUNK: ยิงต่อ
```

### 5.2 กติกาเสริม
| กรณี | ผล |
|---|---|
| กดช่องบนกระดานโจมตีตอนไม่ใช่ตาตัวเอง | ไม่มีอะไรเกิด (เงียบ) |
| ยิงช่องที่เคยยิง | เสียง error, ไม่เสียตา |
| ยิงโดน / ยิงจม | ได้ยิงต่อทันที |
| ยิงพลาด | สลับตา |
| จมเรือลำสุดท้าย | ชนะทันที |
| ยอมแพ้ (สวิตช์ประจำฝั่ง) | อีกฝั่งชนะทันที กดได้ทุกเมื่อใน S3–S4 ไม่ต้องรอตา |

### 5.3 คนยิงก่อน
สุ่ม 50/50 ตอนเข้า S3 (ไม่ใช่ P1 เสมอ)

## 6. AI (ผู้เล่นคอมพิวเตอร์)

### 6.1 สิ่งที่ AI รู้ (เหมือนคนเล่นจริง ไม่โกง)
AI มีตาราง **ความรู้** ของกระดานศัตรู: `UNKNOWN / MISS / HIT / SUNK` และ **จำนวนเรือที่ศัตรูยังเหลือแต่ละขนาด**
AI **ไม่เห็น** `own_board` ของศัตรู

### 6.2 วงจรการยิงของ AI
```
1. pos = select_shot()           (จองช่อง ห้ามเลือกใหม่จนกว่าจะรายงานผล)
2. result = shoot(AI, pos)        (ใช้กติกาเดียวกับคน ข้อ 5.1)
3. report_result(pos, result)     → ช่องนั้นเป็น MISS หรือ HIT
4. ถ้า SUNK: report_sunk(ความยาว, พิกัดทุกช่องของเรือลำนั้น)
             → ช่องเหล่านั้นเป็น SUNK, ลดจำนวนเรือเหลือขนาดนั้น
5. ถ้ายังเป็นตา AI: รอ 0.9 วินาที แล้วกลับข้อ 1
```
ข้อ 4 จำเป็น เพราะเรือวางชิดกันได้ — ถ้าไม่บอกว่าช่องไหนเป็นของลำที่จม AI จะแยกไม่ออกว่า HIT ข้าง ๆ เป็นลำเดียวกันหรือคนละลำ
(ในเกมจริงคนก็รู้ เพราะไฟทุกช่องของลำที่จมเปลี่ยนเป็นสีแดง)

### 6.3 ระดับความยาก
| ระดับ | วิธีเลือกช่อง |
|---|---|
| RANDOM | สุ่มเท่ากันทุกช่องที่ยัง UNKNOWN |
| BALANCED (ค่าเริ่มต้น) | Score map ข้อ 6.4 น้ำหนัก `hunt=10, adjacent=400, line=1200, jitter=0..5` |
| AGGRESSIVE | Score map ข้อ 6.4 น้ำหนัก `hunt=6, adjacent=800, line=2000, jitter=0..3` (ไล่ล่าเรือที่โดนแล้วแรงกว่า) |

### 6.4 Score map (หัวใจของ AI)
ให้คะแนนทุกช่อง UNKNOWN แล้วยิงช่องคะแนนสูงสุด

```
for ความยาว L ที่ศัตรูยังเหลือ (count = จำนวนลำที่เหลือขนาดนั้น):
    for ทุกตำแหน่งและแนวที่เรือยาว L วางได้:
        ตำแหน่งนี้ "เป็นไปได้" ถ้าทุกช่องเป็น UNKNOWN หรือ HIT   (MISS/SUNK = เป็นไปไม่ได้)
        hits = จำนวนช่อง HIT ในตำแหน่งนี้
        for แต่ละช่อง UNKNOWN ในตำแหน่งนี้:
            score += hunt × count                                   ← (ก) โอกาสมีเรือ
            if hits >= 2:                       level = 2 (ต่อแนว)   ← (ข) โหมดล่า
            elif hits == 1 and ช่องนี้ติดกับ HIT ในแนวตำแหน่งนี้: level = 1 (ติดกัน)
            target[ช่อง] = max(target[ช่อง], level)

for แต่ละช่อง UNKNOWN:
    score += line ถ้า target == 2, adjacent ถ้า target == 1
    score += สุ่ม 0..jitter                                         ← (ค) กันเดาทางได้
เลือกช่อง score สูงสุด (เสมอกัน → สุ่ม)
```

- **(ก) โหมดหา (hunt)**: ช่องที่เรือ "วางผ่านได้หลายแบบ" ได้คะแนนสูง → ยิงกลางกระดานก่อน ยิงมุม/ช่องติด MISS ทีหลัง ไม่เสียนัดกับช่องที่เรือที่เหลืออยู่ไม่ได้
- **(ข) โหมดล่า (target)**: เมื่อมี HIT ที่ยังไม่จม ช่องข้าง HIT ได้โบนัสสูงมาก และถ้า HIT สองช่องเรียงกัน ช่องต่อแนวได้โบนัสสูงสุด → ไล่ตามแนวเรือจนจม
- ใช้ `max(level)` ต่อช่อง ไม่บวกซ้ำ → เรือหลายลำชิดกันไม่ทำให้คะแนนเพี้ยน
- ตำแหน่งที่ทับช่อง SUNK ถูกตัดทิ้ง → HIT รอบเรือที่จมแล้วไม่ดึง AI ไปผิดทาง
- **(ค)** เพิ่มความสุ่มเล็กน้อยให้เกมไม่ซ้ำ แต่น้อยกว่าน้ำหนักหลักมาก

### 6.5 ตัวสุ่ม
- xorshift32 (ไม่ใช้ `rand()`), seed ≠ 0
- สุ่มในช่วง `0..n-1` แบบตัดส่วนเกินทิ้ง (ไม่มี modulo bias)
- **seed**: เวลาตอนเปิดเครื่อง ผสมกับ "เวลาที่ P1 กด START" (จังหวะคนทำให้แต่ละเกมไม่ซ้ำ)
- ใส่ seed เดิม → เกมเดิมทุกอย่าง (ใช้ debug/ทดสอบได้)

## 7. ผลลัพธ์ที่ผู้เล่นรับรู้ (Output)

ทุก output **คำนวณจาก state ล่าสุดทั้งหมด** (ไม่สั่งทีละจุด) → วาดใหม่เมื่อ state เปลี่ยน, ไม่มีทางค้างผิด

### 7.1 สีช่อง (ไฟใต้ปุ่ม)
| สถานะ | สี |
|---|---|
| น้ำ | น้ำเงิน 100% |
| ยิงพลาด | น้ำเงิน 15% |
| เรือตัวเอง (ยังไม่โดน) | ขาว |
| โดน | ส้ม |
| จม | แดง ทั้งลำ |
| กำลังวาง (ยังไม่ครบลำ) | ขาวหรี่ |

| State | กระดานเรือ | กระดานโจมตี |
|---|---|---|
| S1, S6 | ดับ | ดับ |
| S2 | น้ำ / เรือ / กำลังวาง | ดับ |
| S3, S4 | น้ำ / เรือ / ผลที่ถูกยิง | น้ำ / ผลที่ตัวเองยิง |
| S5 | เหมือน S4 | **เปิดเผย** เรือศัตรูที่ยังไม่โดนเป็นขาว |

### 7.2 ข้อความ (ต่อฝั่ง)
| State | หัวข้อ | รายละเอียด |
|---|---|---|
| S1 | SELECT MODE | P1: โหมดที่เลือก / P2: รอ P1 |
| S2 | PLACE SHIPS n/6 | เหลือ L3/L2/L1 กี่ลำ หรือ READY รออีกฝั่ง |
| S3 | GAME START | ใครยิงก่อน |
| S4 | YOUR TURN / ENEMY TURN | นัดล่าสุด เช่น `YOU C3 HIT`, เรือเหลือ |
| S5 | YOU WIN! / YOU LOSE | ยอมแพ้หรือไม่, ปุ่มเกมใหม่ |
| S6 | RESETTING | – |
- โหมด 1 คน: อุปกรณ์ฝั่ง AI แสดง `1 PLAYER MODE / AI SIDE`

### 7.3 คำสั่งที่ผู้เล่นกดได้ (ต่อ State)
| State | คำสั่ง |
|---|---|
| S1 | เลือก 1P, เลือก 2P, START (P1 เท่านั้น) |
| S2 | เลือก L1/L2/L3, กดช่องกระดานเรือ, CANCEL, CONFIRM |
| S3 | สวิตช์ยอมแพ้ |
| S4 | กดช่องกระดานโจมตี, สวิตช์ยอมแพ้ |
| S5 | NEW GAME |

## 8. สถาปัตยกรรมที่แนะนำ (เมื่อวางระบบใหม่)

```
 อินพุต (ฮาร์ดแวร์)          ตัวเกม (ไม่รู้จักฮาร์ดแวร์)           เอาต์พุต (ฮาร์ดแวร์)
 ───────────────────        ─────────────────────────         ───────────────────
 แผงสวิตช์ → key(panel,x,y) ─►                              ┌─► ไฟ   (อ่าน state → สี)
 จอสัมผัส/สวิตช์ยอมแพ้ → button(p,cmd) ─►  state machine + กติกา + AI ──┼─► จอ   (อ่าน state → ข้อความ/ปุ่ม)
 นาฬิกา → tick(ms)        ─►                                └─► เสียง (event → ทำนอง)
```

หลักการ:
1. **ตัวเกมรับแค่ 3 อย่าง**: `key(panel, x, y)`, `button(player, command)`, `tick(now_ms)`
2. **ตัวเกมไม่เรียกฮาร์ดแวร์** ยกเว้นแจ้ง "เล่นเสียง X" และตั้ง flag "มีอะไรเปลี่ยน"
3. **Interrupt ส่วนใหญ่แค่เก็บอินพุตใส่คิว** — ตรรกะทำใน main loop
   ยกเว้นสวิตช์ 2 ตัวที่ต้อง "ทันที": ปิดเสียง (ตัดเสียงใน ISR) และยอมแพ้ (จบเกมใน ISR)
   กัน race ด้วย flag `game_busy`: ถ้า loop กำลังแก้สถานะเกมอยู่ ISR จะฝากคำสั่งไว้ แล้วทำทันทีที่ loop ออกจากโค้ดเกม
4. **เอาต์พุตวาดจาก state** เมื่อ flag เปลี่ยนเท่านั้น (ประหยัดเวลา, ไม่ค้างผิด)
5. **กติกาเดียว ใช้ทั้งคนและ AI** (AI ยิงผ่าน `shoot()` ตัวเดียวกับคน)
6. แยกแบบนี้แล้ว **ทดสอบตัวเกมบนคอมได้ 100%** โดยไม่ต้องมีบอร์ด

## 9. กรณีพิเศษที่ต้องรองรับ

| กรณี | การจัดการ |
|---|---|
| กดหลายปุ่มพร้อมกัน | เข้าคิวทีละ event ตามลำดับ (คิวเต็ม = ทิ้ง event ใหม่) |
| สวิตช์เด้ง (bounce) | ต้องนิ่งต่อเนื่อง ~6 ms ถึงนับ, นับเฉพาะตอนกดลง (ไม่นับตอนปล่อย/กดค้าง) |
| กดช่องของอีกฝั่ง/แผงที่ไม่ใช่ state นี้ | ไม่ทำอะไร |
| P2 พยายามเลือกโหมด | ไม่ทำอะไร |
| ฝั่ง AI กดปุ่ม (โหมด 1 คน) | ไม่รับอินพุตจากอุปกรณ์ฝั่ง AI |
| ยอมแพ้ตอน S3 | จบเกมได้เลย |
| AI หาช่องยิงไม่ได้ (ไม่ควรเกิด) | ถือเป็นข้อผิดพลาด → จบเกม ให้คนชนะ |
| ไฟกำลังส่งข้อมูลอยู่ตอนมีอัปเดตใหม่ | จำไว้ ส่งรอบถัดไปเมื่อส่งเสร็จ |
