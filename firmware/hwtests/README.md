## ขั้นตอนเหมือนกันทุกตัว

1. CubeMX: ตั้ง clock 216 MHz + peripheral ของอุปกรณ์นั้น (ตารางในแต่ละหัวข้อ, ชื่อขาตาม [PINOUT.md](../PINOUT.md))
2. เพิ่มไฟล์เข้า build: **ไฟล์ test เพียงไฟล์เดียว** + ไฟล์ไดรเวอร์ในตาราง
   (ห้ามใส่ `app/app.c` หรือ test ไฟล์อื่น เพราะ callback ของ HAL จะซ้ำกัน)
3. Include paths: `hwtests`, `app`, `1_switch`, `2_led`, `4_tft`, `5_lcd`, `sound`, `../core`
4. `main.c` (เฉพาะช่อง USER CODE):
   ```c
   /* USER CODE BEGIN Includes */
   #include "hwtests.h"
   /* USER CODE BEGIN 2 */
   TestLed_Init();          // เปลี่ยนเป็นของ test ที่ใช้
   /* USER CODE BEGIN 3 (ใน while 1) */
   TestLed_Loop();
   ```
5. Build → **Debug** (ไอคอนแมลง) → Resume (F8) → เปิด **Window → Show View → Live Expressions** แล้วพิมพ์ชื่อตัวแปร `test_...`

## 1. ไฟ WS2812 — `test_led.c`

| CubeMX | ค่า |
|---|---|
| TIM1 | CH1–CH4 PWM Generation, Prescaler 0, Period 269 |
| DMA2 | TIM1_CH1..CH4 **Memory to Peripheral**, Normal, Half Word / Half Word |
| ขา | PE9, PE11, PE13, PE14 |
| `app_config.h` | `WS2812_ACTIVE_MASK` = channel ที่ต่อแล้ว (เส้นเดียว = `0x01U`) |

**วิธีทดสอบ**
1. ต่อไฟทีละเส้นตาม BRINGUP.md ข้อ 1.2
2. รัน แล้วดูไฟ

**ผลที่ต้องได้**
- ทุกดวง: แดง → เขียว → น้ำเงิน → ขาว (1.5 วินาที/สี)
- สีประจำ channel: แผง 0 แดง, 1 เขียว, 2 น้ำเงิน, 3 เหลือง
- ไฟวิ่งทีละดวง A1 → H1 → A2 … H7
- Live: `test_led_pattern` วน 1→6, `test_led_frames` เพิ่มขึ้นเรื่อย ๆ

| ถ้า | สาเหตุ / แก้ |
|---|---|
| `test_led_frames` = 0 | interrupt ของ DMA ไม่ทำงาน → NVIC DMA2 stream, ไม่มี callback |
| ไม่ติดเลย แต่ frames เพิ่ม | ฮาร์ดแวร์: GND ร่วม, ขา OE ของ 74AHCT125 ลง GND, เข้า DIN |
| ติดดวงเดียว | ดวงแรกเปลี่ยนสีถูก = สายระหว่างดวง; ไม่ถูก = DMA Direction/Data width |
| แดงกับเขียวสลับ | ไฟใช้ลำดับ RGB → สลับ `c.g`/`c.r` ใน `ws2812.c` |
| ไฟวิ่งผิดลำดับ / สีผิดแผง | `WS2812_SERPENTINE`, `WS2812_FLIP_X/Y`, `WS2812_CHANNEL_TO_PANEL` |

## 1b. ไฟอย่างเดียว ทั้ง 4 เส้น — `test_ws2812b.c`

ไฟล์เดียวจบ **ไม่ต้องตั้ง CubeMX**: TIM1, ขาไฟ 4 ขา และ DMA2 4 stream โค้ดตั้งเอง (เช็ก DMA แบบวนดู ไม่ใช้ interrupt, ไม่มี HAL callback)

**ต่อสาย:** PE9 `CN10-4`, PE11 `CN10-6`, PE13 `CN10-10`, PE14 `CN10-28` → 74AHCT125 1A–4A → 1Y–4Y → 330Ω → DIN เส้น 0–3 · 5V/GND ทุกเส้นจาก PSU · GND ของ PSU ต่อ `CN8-11`

**ลายทดสอบ** (`WS_PATTERN 0` วนครบ ~17 วินาที, ตั้ง 1–5 เพื่อค้างลายเดียว)

| ลาย | เห็น | ใช้ตรวจ |
|---|---|---|
| 1 | ทุกดวง แดง → เขียว → น้ำเงิน → ขาว (1 วินาที/สี) | ลำดับสี · ไฟเลี้ยงพอ: ขาวต้องขาวถึงดวงสุดท้าย ไม่อมเหลือง/แดง |
| 2 | เส้น 0 แดง, 1 เขียว, 2 น้ำเงิน, 3 เหลือง | เส้นไหนต่อขาไหน |
| 3 | ดวงแรกเขียว, ทุก 8 ดวงน้ำเงิน (ต้นแถว), ดวงสุดท้ายแดง, ที่เหลือสลัว | จำนวนดวง + ทิศของเส้น |
| 4 | ไฟขาวดวงเดียววิ่งจากดวงแรกถึงดวงสุดท้าย | วิ่งไปหยุดที่ดวง n = สายขาดหลังดวง n · **ติดพร้อมกันทั้งเส้น = DIN ทุกดวงต่อขนานกัน** |
| 5 | สีรุ้งเลื่อน | |

โค้ดส่งข้อมูลซ้ำ 50 ครั้งต่อวินาทีแม้ลายไม่เปลี่ยน → **ระหว่างลายนิ่ง ถ้าไฟกะพริบหรือมีสีมั่วแว้บ ๆ = สัญญาณ DIN / GND / 5V ของเส้นนั้น** ไม่ใช่โค้ด

Live: `test_ws_timclk` = 216000000, `test_ws_pattern` วน 1→5, `test_ws_frames` เพิ่มเรื่อย ๆ

| ถ้า | สาเหตุ / แก้ |
|---|---|
| `test_ws_frames` ไม่เพิ่ม | โปรแกรมไม่ได้รัน (กด Resume) |
| ไม่ติดเลยทุกเส้น | GND ร่วม, 5V, ขา OE ของ 74AHCT125 (1, 4, 10, 13) ลง GND, เข้า DIN ไม่ใช่ DOUT |
| ไม่ติดเส้นเดียว | สายเส้นนั้น / ช่องนั้นของ 74AHCT125 · สลับสาย DIN กับเส้นที่ติดเพื่อแยกว่าเสียที่แถบไฟหรือที่ทางสัญญาณ |
| เส้นหนึ่งสีมั่ว/เปลี่ยนเองทั้งเส้น | ขา OE ช่องนั้นลอย, GND ไม่ร่วม, 5V ตก, ดวงแรกเสีย (ลองต่อ DIN เข้าดวงที่ 2) |
| ลาย 4 ติดพร้อมกันทั้งเส้น | ต่อ DIN ทุกดวงขนานกัน ต้องต่อ DOUT → DIN เป็นลูกโซ่ |
| แดงกับเขียวสลับ | ไฟลำดับ RGB: สลับ `c.g` กับ `c.r` ใน `put_led()` |
| ลาย 3 แดงไม่อยู่ดวงสุดท้าย | `WS_LEDS` ไม่ตรงจำนวนจริง |

## 2. สวิตช์ Matrix — `test_switch.c`

| CubeMX | ค่า |
|---|---|
| TIM6 | Prescaler 107, Period 199 (200 µs), **NVIC TIM6 on** |
| `COL0..COL7` | PD0, PD1, **PD14**, PD3–PD7 GPIO_Output **Open Drain**, level High |
| `ROW0..ROW27` | GPIO_Input (pull-up 10k ภายนอก หรือ Pull-up ภายใน) |
| ไฟ (ไม่บังคับ) | ถ้าต่อไฟแล้ว: ตั้งแบบ test 1 + เพิ่ม `TEST_SWITCH_WITH_LED=1` ใน Preprocessor defines |

**วิธีทดสอบ**
1. ต่อแผงทีละแผง (คอลัมน์ 8 + แถว 7 ของแผงนั้น)
2. Live Expressions: `test_key_count`, `test_last_panel`, `test_last_x`, `test_last_y`, `test_seen`, `test_seen_map`, `keypad_debug_raw`
3. กดทุกปุ่ม 56 ปุ่มทีละปุ่ม

**ผลที่ต้องได้**
- กด 1 ครั้ง `test_key_count` +1, `test_last_*` ตรงกับปุ่มที่กด (x 0 = A, y 0 = แถว 1)
- กดครบ → `test_seen[แผง]` = **56** และ `test_seen_map[แผง][0..6]` = **0xFF** ทุกแถว
- (ถ้าเปิดไฟ) ไฟช่องเดียวกับปุ่มกลายเป็นขาว, ล่าสุดแดง, แต่ละแผงพื้นสีต่างกัน
- ไม่กดอะไร: `keypad_debug_raw[0..7]` = 0 ทุกตัว

| ถ้า | สาเหตุ / แก้ |
|---|---|
| `test_seen_map` ขาดบิตเดียว | ปุ่ม/ไดโอดตัวนั้น (ไดโอดกลับทิศ) |
| ขาดทั้งแถว (ค่า 0x00 ทั้งแถว) | สายแถวนั้นหลุด หรือชื่อขา ROW ผิด |
| ขาดบิตเดียวกันทุกแถว | สายคอลัมน์นั้น |
| `keypad_debug_raw` ไม่เป็น 0 ทั้งที่ไม่กด | แถวไม่มี pull-up / ลัดลง GND |
| x หรือ y กลับด้าน | `KEYPAD_FLIP_X/Y` · แผงผิด → `KEYPAD_GROUP_TO_PANEL` |
| กดทีเดียวนับ 2 | เพิ่ม `KEYPAD_DEBOUNCE_SCANS` |

ทดสอบ ghosting: กดค้าง 3 ปุ่มเป็นรูปตัว L → `test_key_count` ต้องเพิ่มแค่ 3

## 2b. ปุ่ม + ไฟ ทั้ง 4 ตาราง — `test_table.c`

ไฟล์เดียวจบ **ไม่ต้องตั้ง CubeMX**: ขาสวิตช์ 36 ขา, ขาไฟ 4 ขา, TIM1 และ DMA2 4 stream โค้ดตั้งเองทั้งหมด
(เช็ก DMA แบบวนดู ไม่ใช้ interrupt จึงไม่ชนกับที่ CubeMX ตั้งไว้) · ไม่มี HAL callback อยู่ใน build ร่วมกับเทสต์อื่นได้
ต่อไม่ครบ 4 ตารางก็ใช้ได้ ตารางที่ไม่ได้ต่อจะไม่มีอะไรเกิดขึ้น

**ต่อสาย** (ตาม PINOUT.md) คอลัมน์ 8 เส้นใช้ร่วมกันทุกตาราง

| | ขา Nucleo |
|---|---|
| คอลัมน์ A–H (ทุกตาราง) | PD0 `CN9-25`, PD1 `CN9-27`, PD14 `CN7-16`, PD3 `CN9-10`, PD4 `CN9-8`, PD5 `CN9-6`, PD6 `CN9-4`, PD7 `CN9-2` |
| แถว 1–7 ตาราง 0 เรือ P1 | PF0, PF1, PF2, PF3, PF4, PF5, PE15 |
| แถว 1–7 ตาราง 1 โจมตี P1 | PF7, PF8, PF9, PF10, PB10, PF12, PF13 |
| แถว 1–7 ตาราง 2 เรือ P2 | PF14, PF15, PG0, PG1, PG2, PG3, PB11 |
| แถว 1–7 ตาราง 3 โจมตี P2 | PD11, PD12, PG9, PD13, PB2, PG14, PB6 |
| ไฟ DIN ตาราง 0–3 | PE9 `CN10-4`, PE11 `CN10-6`, PE13 `CN10-10`, PE14 `CN10-28` → 74AHCT125 (1A, 2A, 3A, 4A) → 330Ω → DIN |

ตำแหน่ง CNx-n ของทุกขาแถวอยู่ใน PINOUT.md · แถวใช้ pull-up ในชิป · ไฟ 4 ตารางใช้ PSU 5V (ขาวทั้งหมด ~3.4 A ที่ความสว่างนี้)

**ผลที่ต้องได้**
1. เปิดมา แต่ละตารางติดสลัวคนละสี: ตาราง 0 **ขาว**, 1 **ฟ้า**, 2 **ส้ม**, 3 **ม่วง** (สีผิดตาราง = สายไฟ LED สลับเส้น)
2. กดช่องไหน ไฟช่องนั้นเปลี่ยนสีถัดไป: แดง → ส้ม → เหลือง → เขียว → ฟ้า → น้ำเงิน → ม่วง → ขาว → แดง …
3. สองฝั่งกดพร้อมกันได้
4. ตารางไหนกดครบ 56 ช่อง ตารางนั้นกะพริบเขียว 3 ครั้ง

Live: `test_tbl_seen` (4 ช่อง เป้า 56 ทุกตาราง), `test_tbl_last_table`, `test_tbl_last_x` (0–7 = A–H), `test_tbl_last_y` (0–6 = แถว 1–7), `test_tbl_raw` (กดค้างแล้วดู), `test_tbl_ghost`, `test_tbl_frames` (เพิ่มเมื่อมีการกด)

**ตั้งค่าบนสุดของไฟล์** (แต่ละค่ามี 4 ช่อง `{ ตาราง0, 1, 2, 3 }`)

| ไฟเปลี่ยนผิดช่อง | ดู `test_tbl_last_x/_y` หลังกด | แก้ |
|---|---|---|
| x/y ผิดจากช่องที่กด | สายปุ่มกลับด้าน | `KEY_FLIP_X` / `KEY_FLIP_Y` |
| x/y ถูก แต่ไฟติดผิดที่ | ลำดับไฟกลับด้าน | `LED_FLIP_X` / `LED_FLIP_Y` |
| ผิดเฉพาะแถวคู่ | ไฟเดินแบบงู | `LED_SERPENTINE` |

ได้ค่าที่ถูกแล้ว ใส่ค่าเดียวกันใน `app_config.h` (`KEYPAD_FLIP_*`, `WS2812_FLIP_*`, `WS2812_SERPENTINE`)

| ถ้า | สาเหตุ / แก้ |
|---|---|
| กด 1 ครั้งเปลี่ยน 2 สีขึ้นไป | ปุ่มเด้ง/บัดกรีไม่แน่น · หรือเพิ่ม `DEBOUNCE_SCANS` |
| กดตาราง A แต่ไฟขึ้นตาราง B | `test_tbl_last_table` ผิด = สายแถวต่อผิดกลุ่ม · ถูก = สายไฟ LED สลับเส้น |
| กดแล้วไม่มีอะไรเพิ่ม | กดค้างแล้วดู `test_tbl_raw[คอลัมน์]`: 0 = สายคอลัมน์/แถวขาด หรือไดโอดกลับทิศ |
| ทั้งคอลัมน์ไม่ขึ้นทุกตาราง | สายคอลัมน์เส้นนั้นขาดก่อนแยกไปตาราง |
| ทั้งแถวของตารางเดียวไม่ขึ้น | สายแถวเส้นนั้นขาด |
| กดช่องเดียวขึ้นหลายช่อง | สองคอลัมน์หรือสองแถวช็อตกัน |
| กดหลายปุ่มแล้ว `test_tbl_ghost` เพิ่ม (ช่องผี) | ไดโอดเสีย/กลับทิศ/ช็อต: กด 3 ปุ่มเป็นรูปตัว L ถ้า ghost เพิ่ม ปุ่ม**มุมของตัว L** ไดโอดเสีย · วัด: มิเตอร์โหมดไดโอด กดปุ่มค้าง สายแดงที่แถว สายดำที่คอลัมน์ ต้องได้ ~0.5–0.7 V และสลับสายต้องได้ OL |
| ตารางหนึ่งไม่ติดเลย | สาย DIN/5V/GND ของตารางนั้น · 74AHCT125 ช่องนั้น · ขา OE ลง GND |

## 3. Buzzer + สวิตช์ปิดเสียง — `test_buzzer.c`

| CubeMX | ค่า |
|---|---|
| TIM3 | CH1, CH2 PWM Generation, Prescaler 107 (1 MHz), Period 999 · ขา PC6, PC7 |
| `MUTE1`, `MUTE2` | PE0 (EXTI0), **PB1** (EXTI1) GPIO_EXTI **Rising/Falling**, Pull-up · NVIC EXTI0, EXTI1 on |

**วิธีทดสอบ**
1. รัน แล้วฟัง: เสียงทั้ง 7 แบบ ห่างกัน 1.5 วิ วนเป็นชุด **P1 อย่างเดียว → P2 อย่างเดียว → ทั้งคู่**
2. ระหว่างเสียงดัง เลื่อนสวิตช์ปิดเสียง P1
3. Live: `test_sound`, `test_side` (1 = P1, 2 = P2, 3 = ทั้งคู่), `test_muted`, `test_mute_edges`

**ผลที่ต้องได้**
- รอบ `test_side = 1` ดังเฉพาะ buzzer P1, รอบ 2 เฉพาะ P2
- เสียงแต่ละแบบต่างกันชัด (คลิก, บึ้บ ๆ, ตกลง, ขึ้น, ไล่ลง 4 โน้ต, เริ่มเกม, จบเกม)
- เลื่อนปิดเสียง → ฝั่งนั้น**เงียบทันที**กลางเสียง, อีกฝั่งดังต่อ, `test_muted[0]` = 1, `test_mute_edges[0]` +1 ต่อการเลื่อน 1 ครั้ง

| ถ้า | สาเหตุ / แก้ |
|---|---|

## 3b. ปุ่มยอมแพ้ + ปิดเสียง + buzzer แบบไฟล์เดียว — `test_side.c`

ไม่ต้องตั้ง CubeMX: TIM3 และขา 6 ขาโค้ดตั้งเอง สวิตช์อ่านแบบวนดู (ไม่ใช้ EXTI) · ไม่มี HAL callback

|---|---|---|

- เลื่อนสวิตช์ปิดเสียง: ฝั่งนั้นเงียบ แม้กดปุ่มยอมแพ้ · เลื่อนกลับ: มีเสียง "ติ๊ด" สั้น ๆ

Live: `test_side_surr` (1 ขณะกด), `test_side_surr_count` (กด 1 ครั้ง +1), `test_side_mute` (1 = ปิดเสียง), `test_side_hz` (ความถี่ที่ดังอยู่)

| ถ้า | สาเหตุ / แก้ |
|---|---|
| `test_side_hz` มีค่าแต่ไม่มีเสียง | วงจร buzzer: 1k เข้าขา B, ขา E ลง GND, buzzer + ไป 5V, − ไปขา C · ขาของ 2N2222 แต่ละยี่ห้อเรียงต่างกัน เช็ก datasheet |
| ดังตลอดแม้ไม่กดอะไร | ทรานซิสเตอร์ช็อต C–E หรือต่อ buzzer ตรง 5V–GND |

| `test_side_mute` ไม่เปลี่ยนตอนเลื่อน | ต่อเข้าขากลางของสวิตช์ และขาข้างหนึ่งลง GND |
| เสียงเบา | buzzer แบบ passive ดังสุดราว 2–4 kHz: ปรับ `TONE_P1_HZ` / `TONE_P2_HZ` |

## 5b. LCD 16x2 สองจอ แบบไฟล์เดียว — `test_lcd16x2.c`

ไม่ต้องตั้ง I2C ใน CubeMX: โค้ดขับ PB8/PB9 เป็น I2C เอง (software I2C) · ไม่มี HAL callback อยู่ร่วมกับเทสต์อื่นใน build ได้

**ต่อสาย** สองจอต่อขนานกันบนสาย 4 เส้นเดียวกัน

| ขาโมดูล I2C | Nucleo |
|---|---|
| GND | `CN8-11` GND |
| VCC | `CN8-9` +5V (ไฟ USB พอสำหรับ 2 จอ) |
| SDA | PB9 `CN7-4` |
| SCL | PB8 `CN7-2` |

**address:** จอ P1 = 0x27 (ไม่บัดกรีจัมเปอร์ A0 A1 A2) · จอ P2 = 0x26 (**บัดกรี A0** อย่างเดียว)

**ผลที่ต้องได้**
- บรรทัดบน: `LCD P1  ADDR 27` และ `LCD P2  ADDR 26`
- บรรทัดล่างเปลี่ยนทุก 2 วินาที: `ABCDEFGHIJKLMNOP` → บล็อกเต็ม 16 ช่อง → `0123456789 T0012` (นับวินาที)
- Live: `test_lcd_bus_ok` = 1, `test_lcd_count` = 2, `test_lcd_addr` = {0x26, 0x27}, `test_lcd_nack` = 0
- ตรวจบัสทุก 1 วินาที จอที่เพิ่งได้ไฟ/เพิ่งต่อจะขึ้นเอง

| ถ้า | สาเหตุ / แก้ |
|---|---|
| ไฟจอติด เห็นแต่แถบสี่เหลี่ยม หรือไม่เห็นอะไร | หมุน contrast (ตัวต้านทานปรับค่าสีฟ้าหลังโมดูล) ตอนบรรทัดล่างเป็นบล็อกเต็ม |
| `test_lcd_bus_ok` = 0 | SDA/SCL ถูกดึงลง: โมดูลไม่มีไฟ 5V, ช็อต GND, หรือโมดูลไม่มี pull-up |
| `test_lcd_count` = 0, bus ok | SDA/SCL สลับกัน หรือสายหลุด |
| ทั้งสองจอขึ้น `LCD P1 ADDR 27` เหมือนกัน, count = 1 | address ชน: บัดกรี A0 ของจอ P2 |
| ขึ้น `LCD ??  ADDR 3F` / `3E` | ชิป PCF8574A: ตั้ง `LCD_I2C_ADDR` ใน `app_config.h` ตามเลขที่เห็น |
| `test_lcd_nack` เพิ่มเรื่อย ๆ / ตัวอักษรเพี้ยน | สายหลวมหรือยาวเกิน |
| ไฟหลังจอดับ | จัมเปอร์ backlight หลังโมดูลหลุด |

## 6. จอ TFT — `test_tft.c`

| CubeMX | ค่า |
|---|---|
| SPI1 | Transmit Only Master, 8-bit, CPOL Low, CPHA 1 Edge, Prescaler 4 · PA5, PA6, PB5 |
| DMA2 | SPI1_TX **Stream 5**, Memory to Peripheral, Normal, Byte/Byte · NVIC DMA2 stream5 on |
| GPIO Output (High) | `CS` PC8, `DC` PC9, `RST` PC10, `CS2` PC11, `DC2` PD15, `RST2` PD2 |

**วิธีทดสอบ**
1. รัน, ดูทั้งสองจอ · Live: `test_tft_full_ms`, `test_tft_band_ms`, `test_tft_updates`

**ผลที่ต้องได้**
- บนสุด: แถบสี **R G B W** เรียงจากซ้าย
- `TOP LEFT` อยู่มุมซ้ายบน, `BOTTOM RIGHT` มุมขวาล่าง, เห็นกรอบขาว 1 px ครบ 4 ด้าน
- ตัวใหญ่ `TFT 1` บนจอ P1, `TFT 2` บนจอ P2, แถบเทาไล่ 16 ระดับ
- `UPDATE n` เพิ่มขึ้นทุก 250 ms สลับจอ (ทดสอบส่งเฉพาะแถบผ่าน DMA)
- เวลา (SPI 27 MHz): full ≈ 45 ms, band ≈ 5 ms · ถ้าใช้ prescaler 8: ≈ 91 / 10 ms

| ถ้า | สาเหตุ / แก้ |
|---|---|
| จอขาวล้วน | CS/DC/RST ผิดขา, ไม่มีไฟเลี้ยง, ค้างที่ init |
| R กับ B สลับ | `TFT_MADCTL` ใน `tft.c`: 0x48 ↔ 0x40 |
| กลับด้าน/หมุน (TOP LEFT ไม่อยู่ซ้ายบน) | ลอง `TFT_MADCTL` 0x88, 0x08, 0xC8 |
| ภาพเป็นจุดเพี้ยน | Prescaler 8 หรือ 16, สายให้สั้น |
| `UPDATE` ไม่เพิ่ม / ค้าง | DMA SPI1_TX ไม่ได้ตั้ง / NVIC ปิด (busy ค้าง) |
| ขึ้นผิดจอ | สลับสาย CS กับ CS2 |

## 7. จอสัมผัส + คาลิเบรต — `test_touch.c` (ทำหลัง test 6 ผ่าน)

| CubeMX | ค่า |
|---|---|
| ทุกอย่างของ test 6 | |
| GPIO Output (Very High) | `T_CLK` PE3, `T_MOSI` PE5, `T_CS` PE6 (High), `T_CS2` PE7 (High) |
| GPIO Input | `T_MISO` PE4 |
| GPIO_EXTI Falling, Pull-up | `T_IRQ` PE2, `T_IRQ2` PE8 · NVIC EXTI2, EXTI9_5 on |

**วิธีทดสอบ (ทำทีละจอ)**
1. จอแสดงเป้า 4 จุด แตะตามลำดับ **1 ซ้ายบน → 2 ขวาบน → 3 ขวาล่าง → 4 ซ้ายล่าง** (เป้าถัดไปเป็นสีแดง แตะแล้วเป็นเขียว)
2. ครบ 4 จุด จอแสดงค่า **X_MIN X_MAX Y_MIN Y_MAX SWAP_XY** (หรือดู `test_cal[จอ][0..4]`)
3. ใส่ค่าลง `app_config.h` (ตำแหน่ง P1 = ตัวแรก, P2 = ตัวที่สอง ของแต่ละบรรทัด):
   ```c
   #define TOUCH_RAW_X_MIN        { <X_MIN จอ1>, <X_MIN จอ2> }
   #define TOUCH_RAW_X_MAX        { <X_MAX จอ1>, <X_MAX จอ2> }
   #define TOUCH_RAW_Y_MIN        { ... }
   #define TOUCH_RAW_Y_MAX        { ... }
   #define TOUCH_SWAP_XY          { <SWAP จอ1>, <SWAP จอ2> }
   ```
4. Build + รันใหม่ ทำครบ 4 จุดอีกรอบ แล้วแตะที่ไหนก็ได้

**ผลที่ต้องได้**
- แตะ 1 ครั้ง `#n` +1 (ไม่ใช่ +2), ค่า RAW เปลี่ยนตามตำแหน่ง
- หลังใส่ค่าแล้ว: **กากบาทแดงขึ้นใต้นิ้ว** ทุกมุม คลาดไม่เกิน ~5 px
- แตะจอ P1 แล้วจอ P2 ไม่เปลี่ยน (และกลับกัน)

| ถ้า | สาเหตุ / แก้ |
|---|---|
| แตะแล้วไม่มีอะไร | T_IRQ ไม่ลง LOW/EXTI ไม่เปิด, T_CS ผิดจอ |
| RAW เป็น 0 หรือ 4095 ตลอด | T_MISO/T_MOSI สลับ, T_CLK ไม่ต่อ |
| ค่ากระโดดมาก | กดเบาไป (resistive ต้องกดลงไป), สายยาว |
| แตะจอ P1 แต่จอ P2 ตอบ | สลับสาย T_CS/T_CS2 หรือ T_IRQ/T_IRQ2 |

## 7b. จอ TFT สองจอ + touch แบบไฟล์เดียว — `test_tft_touch.c`

ไม่ต้องตั้ง CubeMX: SPI1 (แบบวนส่ง ไม่ใช้ DMA) และทุกขาโค้ดตั้งเอง · จอเริ่มทำงานตอนเรียก Loop ครั้งแรก (~1.5 วินาที)

**ต่อสาย** (ตาม PINOUT.md)

| | จอ P1 | จอ P2 |
|---|---|---|
| SCK / SDI(MOSI) | PA5 `CN7-10` / PB5 `CN7-13` (ใช้ร่วม) | ← |
| CS / DC / RESET | PC8 / PC9 / PC10 | PC11 / PD15 / PD2 |
| T_CLK / T_DIN / T_DO | PE3 / PE5 / PE4 (ใช้ร่วม) | ← |
| T_CS / T_IRQ | PE6 / PE2 | PE7 / PE8 |
| VCC, LED / GND | 3.3V `CN8-7` / GND | ← |

SDO (MISO) ของจอไม่ต้องต่อ

**สิ่งที่เห็นบนแต่ละจอ**
- ขอบ: จอ P1 **แดง**, จอ P2 **น้ำเงิน**
- มุมซ้ายบน: เลข **1** หรือ **2** ตัวใหญ่ (ถ้าไปอยู่มุมอื่นหรือกลับด้าน = ทิศจอผิด แก้ `TFT_MADCTL`)
- ขวาบน: สี่เหลี่ยม แดง เขียว น้ำเงิน ขาว (แดงกับน้ำเงินสลับ → `TFT_MADCTL 0x40`)
- กลาง: ค่า touch ดิบล่าสุด X (ฟ้า) และ Y (ชมพู)
- ล่าง: พื้นที่วาด แตะลากแล้วมีจุดเหลืองตามนิ้ว · แตะส่วนบน (เหนือเส้นเทา) = ล้างภาพ

**คาลิเบรต:** ลากนิ้วไปตามขอบทั้ง 4 ด้านของจอ แล้วอ่าน `test_tft_raw_min` / `test_tft_raw_max` ของจอนั้น ([0] = X, [1] = Y)
ใส่ใน `TOUCH_X_MIN/MAX`, `TOUCH_Y_MIN/MAX` บนสุดของไฟล์ และ `TOUCH_RAW_*` ใน `app_config.h` · จุดเลื่อนผิดแกน (ลากขวาแต่จุดขึ้นบน) → `TOUCH_SWAP_XY`

Live: `test_tft_irq` (1 ขณะแตะ), `test_tft_touches`, `test_tft_raw`, `test_tft_raw_min`, `test_tft_raw_max`, `test_tft_xy`

| ถ้า | สาเหตุ / แก้ |
|---|---|
| จอขาวทั้งจอ | ไม่ได้รับคำสั่ง: SCK/MOSI/CS/DC/RESET ของจอนั้น, GND · หรือ SPI เร็วไปสำหรับสายยาว → `TFT_SPI_BR 2` หรือ `3` |
| ภาพมีจุดเพี้ยน/สีเลอะ | สาย SPI ยาว/หลวม → `TFT_SPI_BR 2` |
| จอหนึ่งขึ้นภาพของอีกจอ หรือสองจอเหมือนกัน | CS สลับกันหรือช็อตกัน |
| แตะแล้ว `test_tft_irq` ไม่เป็น 1 | สาย T_IRQ ของจอนั้น |
| `test_tft_irq` = 1 แต่ `test_tft_touches` ไม่เพิ่ม | อ่านค่าไม่ได้: T_CLK/T_DIN/T_DO/T_CS |
| จุดไม่อยู่ใต้นิ้ว | คาลิเบรต (ด้านบน) |
