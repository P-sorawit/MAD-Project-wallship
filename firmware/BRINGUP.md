# แผนการต่อวงจร และการทดสอบทีละอุปกรณ์

ใช้คู่กับ [PINOUT.md](PINOUT.md) (ขา) และโหมดทดสอบฮาร์ดแวร์ `app/hwtest.c`
หลักการ: **ต่อทีละอุปกรณ์ → ทดสอบผ่าน → ค่อยต่อชิ้นถัดไป** ถ้าพังจะรู้ทันทีว่าเกิดจากชิ้นไหน

> ⚠ ทุกครั้งก่อนต่อ/ถอดสาย: **ถอด USB และปิด PSU ก่อน**

## ส่วนที่ 1 แผนการต่อ

### 1.1 ไฟเลี้ยงและกราวด์

```
                 ┌────────────────────────────────────────────────┐
 PSU 5V 10A ─────┤ +5V rail (สาย AWG20)                           │
                 │   ├── แถบไฟ 4 แผง (+ 1000µF คร่อมที่ต้นแต่ละแผง) │
                 │   ├── 74AHCT125 ขา 14 (VCC) + 100nF ลง GND      │
                 │   ├── buzzer ×2 (ผ่านวงจรทรานซิสเตอร์ ข้อ 1.4)    │
                 │   ├── LCD1602 ×2 (VCC)                          │
                 │   └── Nucleo E5V (CN11 ขา 6) ★ เฉพาะตอนประกอบจริง │
                 │                                                │
 PSU GND ────────┤ GND rail ── ทุกอุปกรณ์ + GND ของ Nucleo (ต้องต่อ)  │
                 └────────────────────────────────────────────────┘
 Nucleo 3.3V ─── จอ TFT ×2 (VCC + LED), pull-up 10k ของแถวสวิตช์ 28 ตัว
```

| ช่วง | ไฟเลี้ยง Nucleo | จัมเปอร์ JP3 |
|---|---|---|
| ระหว่างพัฒนา/ทดสอบ | USB อย่างเดียว (**ห้ามต่อ E5V**) | U5V |
| ประกอบจริง | PSU → E5V | **E5V** |

- GND ทุกอย่างต้องรวมกัน (PSU, Nucleo, แถบไฟ, 74AHCT125, จอ) ไม่งั้นสัญญาณไม่มีจุดอ้างอิง
- ห้ามป้อน 5V เข้าขา `5V` ของ Nucleo ระหว่างเสียบ USB

### 1.2 ไฟ WS2812 ×4 ผ่าน 74AHCT125

**ขาของ 74AHCT125 (DIP-14)**
```
        ┌───∪───┐
 1OE  1 │       │ 14 VCC (5V)
  1A  2 │       │ 13 4OE
  1Y  3 │       │ 12 4A
 2OE  4 │       │ 11 4Y
  2A  5 │       │ 10 3OE
  2Y  6 │       │  9 3A
 GND  7 │       │  8 3Y
        └───────┘
 ขา OE ทั้ง 4 (1, 4, 10, 13) ต่อ GND (active low = เปิดใช้งาน)
```

| Nucleo | 74AHCT125 เข้า | 74AHCT125 ออก | ผ่าน | ไปที่ |
|---|---|---|---|---|
| PE9 (TIM1_CH1) | ขา 2 (1A) | ขา 3 (1Y) | 330Ω | DIN แผง 0 เรือ P1 |
| PE11 (TIM1_CH2) | ขา 5 (2A) | ขา 6 (2Y) | 330Ω | DIN แผง 1 โจมตี P1 |
| PE13 (TIM1_CH3) | ขา 9 (3A) | ขา 8 (3Y) | 330Ω | DIN แผง 2 เรือ P2 |
| PE14 (TIM1_CH4) | ขา 12 (4A) | ขา 11 (4Y) | 330Ω | DIN แผง 3 โจมตี P2 |

- ลำดับดวงในแผง (ค่าเริ่มต้นของโค้ด): ดวงแรก = **A1** (มุมซ้ายบน) → B1 … H1 → A2 … H7
  ถ้าเดินแบบงู (แถวคู่ย้อนกลับ) ตั้ง `WS2812_SERPENTINE 1`
- ต่อเข้า **DIN** ตามลูกศรบนสาย ห้ามเข้า DOUT
- 1000µF 16V คร่อม 5V–GND ที่ต้นแผง (ขั้วบวกเข้า 5V)

### 1.3 สวิตช์ Matrix (4 แผง × 56 ปุ่ม)

**ปุ่ม 1 ตัว**
```
  แถว ROWn ───►|─── สวิตช์ ─── คอลัมน์ COLm
            แอโนด  แคโทด
         (1N4148: ขีดดำ = แคโทด หันไปทางคอลัมน์)

  3.3V ── 10k ── แถว ROWn         (pull-up แถวละ 1 ตัว รวม 28 ตัว)
```

| สาย | ขา Nucleo | ต่อกับ |
|---|---|---|
| คอลัมน์ A..H | PD0, PD1, **PD14**, PD3, PD4, PD5, PD6, PD7 (`COL0..7`) | คอลัมน์เดียวกันของ**ทั้ง 4 แผง**ต่อขนานกัน |
| แถว 1..7 แผง 0 (เรือ P1) | PF0, PF1, PF2, PF3, PF4, PF5, **PE15** (`ROW0..6`) | |
| แถว 1..7 แผง 1 (โจมตี P1) | PF7, PF8, PF9, PF10, **PB10**, PF12, PF13 (`ROW7..13`) | |
| แถว 1..7 แผง 2 (เรือ P2) | PF14, PF15, PG0, PG1, PG2, PG3, **PB11** (`ROW14..20`) | |
| แถว 1..7 แผง 3 (โจมตี P2) | **PD11, PD12**, PG9, **PD13, PB2**, PG14, **PB6** (`ROW21..27`) | |

ตำแหน่งบน header (CNx-n) ของทุกขา: [PINOUT.md](PINOUT.md) v4 หรือแผนภาพ [docs/wiring.html](../docs/wiring.html)

- pull-up ต่อ **3.3V** ไม่ใช่ 5V
- ทิศไดโอดผิด = ปุ่มนั้นกดไม่ติดเลย (ตรวจเจอในขั้นทดสอบ)

### 1.4 Buzzer ×2

```
  5V ───────┬──────────────┐
            │              │
       buzzer (+)      1N4148 แคโทด (ขีดดำ)
       buzzer (−)      1N4148 แอโนด
            │              │
            ├──────────────┘      ← ไดโอดคร่อม buzzer อย่างเดียว
          [100Ω]
            │
            C
  PC6 ─1k─ B   2N2222            (P1 = PC6, P2 = PC7)
            E
            │
           GND
```
- ไดโอดคร่อม buzzer (แบบแม่เหล็กเป็นขดลวด) กันแรงดันย้อนตอนทรานซิสเตอร์ตัด — proposal ไม่ได้ใส่ไว้ แนะนำให้เพิ่ม
- ขาของ 2N2222 แบบ TO-92 มักเป็น E-B-C (มองด้านแบน) แต่บางยี่ห้อต่าง **เช็ก datasheet ของตัวที่ซื้อ**

### 1.5 สวิตช์ปิดเสียง ×2 และ สวิตช์ยอมแพ้ ×2

```
  ปิดเสียง (สไลด์ SPDT)            ยอมแพ้ (ปุ่มกด ปกติเปิด)
  PE0 ─── ขากลาง                   PE10 ─── ปุ่ม ─── GND
          ขาข้าง 1 ─── GND
          ขาข้าง 2 ─── (ว่าง)
  เลื่อนไปฝั่ง GND = ปิดเสียง        กด = ยอมแพ้
```
| ฝั่ง | ปิดเสียง | ยอมแพ้ |
|---|---|---|
| P1 | PE0 (`MUTE1`) | PE10 (`SURR1`) |
| P2 | PB1 (`MUTE2`) | PE12 (`SURR2`) |
ใช้ pull-up ในชิป (ตั้งใน CubeMX) ไม่ต้องใส่ตัวต้านทาน

### 1.6 LCD1602 ×2 (โมดูล I2C)

| ขาโมดูล | P1 (0x27) | P2 (0x26) |
|---|---|---|
| VCC | 5V | 5V |
| GND | GND | GND |
| SDA | PB9 | PB9 (ขนาน) |
| SCL | PB8 | PB8 (ขนาน) |
| จัมเปอร์ A0/A1/A2 | ไม่บัดกรี | **บัดกรี A0** |

### 1.7 จอ TFT ×2 + Touch

| ขาโมดูล | จอ P1 | จอ P2 |
|---|---|---|
| VCC, LED | 3.3V | 3.3V |
| GND | GND | GND |
| CS / DC / RESET | PC8 / PC9 / PC10 | PC11 / PC12 / PD2 |
| SDI(MOSI) / SCK / SDO(MISO) | PB5 / PA5 / PA6 | ขนานกับจอ P1 |
| T_CLK / T_DIN / T_DO | PE3 / PE5 / PE4 | ขนานกับจอ P1 |
| T_CS / T_IRQ | PE6 / PE2 | PE7 / PE8 |

- สาย SPI ยาวเกิน ~20 cm ภาพอาจเพี้ยน → ลดความเร็ว SPI (prescaler 8 หรือ 16)

## ส่วนที่ 2 ลำดับการทดสอบ

### เตรียมโปรแกรม
มีโค้ดทดสอบ 2 แบบ:
- **ทีละอุปกรณ์** (แนะนำระหว่างต่อสาย): [hwtests/](hwtests/README.md) — ไฟล์ละอุปกรณ์ ตั้ง CubeMX แค่ส่วนนั้นก็ใช้ได้ พร้อมวิธีทดสอบและตารางแก้ปัญหาของแต่ละตัว
- **รวมทุกอุปกรณ์**: `APP_HW_TEST 1` (ด้านล่าง) — ใช้ตอนต่อครบแล้ว ตรวจรวมก่อนเล่นเกม

1. สร้างโปรเจกต์ CubeIDE ตาม PINOUT.md (ตั้งครบทุกขาได้เลย ขาที่ยังไม่ต่อไม่เป็นไร)
2. ใน `app/app_config.h` ตั้ง **`#define APP_HW_TEST 1`** → โปรแกรมจะเข้าโหมดทดสอบแทนเกม
3. ระหว่างทดสอบไฟทีละเส้น ตั้ง `WS2812_ACTIVE_MASK` ให้ตรงกับเส้นที่ต่อแล้ว
4. ใช้ **Debug → Live Expressions** ดูตัวแปรได้ เช่น `key_count`, `surr_count`, `touch_raw`, `found_addr`

### ผลที่โหมดทดสอบแสดง

| อุปกรณ์ | ดูผลที่ |
|---|---|
| ไฟ | ลายทดสอบ → พอกดปุ่มแรก เปลี่ยนเป็นแผนที่ปุ่ม (แต่ละแผงสีจาง ๆ ต่างกัน, ช่องที่กด = ขาว, ล่าสุด = แดง) |
| สวิตช์ | ไฟช่องนั้นสลับขาว + เสียงคลิกฝั่งนั้น + จำนวนกดบน LCD/TFT |
| buzzer | เปิดเครื่องมีเสียง START, กดปุ่มมีเสียงคลิก, กดยอมแพ้มีเสียง SUNK |
| ปิดเสียง/ยอมแพ้ | `MUTE:ON/OFF`, `SURR n` บน LCD และ TFT |
| LCD | ผลสแกน I2C บนจอ TFT, ข้อความบน LCD |
| TFT | แถบสี R G B W, ข้อความ TOP LEFT, กรอบขาวรอบจอ, ค่า touch ดิบ + เป้าแดงตรงที่แตะ |

### ขั้นที่ 0 — ตรวจไฟก่อนเสียบอะไร (มัลติมิเตอร์)
| ตรวจ | ผลที่ต้องได้ |
|---|---|
| PSU ไม่มีโหลด | 5.0–5.2 V |
| +5V rail กับ GND (ปิดไฟ, โหมดวัดความต่อเนื่อง) | **ไม่บี๊บ** (ไม่ลัดวงจร) |
| 3.3V ของ Nucleo (เสียบ USB) | 3.3 V |
| GND PSU ↔ GND Nucleo | บี๊บ (ต่อถึงกัน) |

### ขั้นที่ 1 — Nucleo เปล่า
- ต่อ: USB อย่างเดียว · ทำ: build + Run โปรแกรม (`APP_HW_TEST 1`)
- ผ่านเมื่อ: Debug ได้, `HAL_GetTick()` เพิ่มขึ้น, ไม่ค้างที่ HardFault
- ไม่ผ่าน: เช็ก clock 216 MHz, ไฟล์ครบใน build

### ขั้นที่ 2 — ไฟเส้นที่ 1 (แผง 0)
- ต่อ: PE9 → 74AHCT125 → 330Ω → DIN, 5V/GND จาก PSU · ตั้ง `WS2812_ACTIVE_MASK 0x01U`
- ผ่านเมื่อ: **ทุกดวง**วน แดง → เขียว → น้ำเงิน → ขาว → แดงทั้งแผง (สีของ CH1) → ไฟวิ่ง A1, B1 … H7
| อาการ | แก้ |
|---|---|
| ไม่ติดเลย | GND ร่วม, OE ลง GND, DMA Direction = Memory→Peripheral |
| ติดดวงเดียว | ดวงแรกเปลี่ยนสีถูก = สายระหว่างดวงขาด/กลับทิศ; ไม่เปลี่ยน = timing/DMA ผิด |
| แดง↔เขียวสลับ | ลำดับ RGB → สลับ `c.g` กับ `c.r` ใน `ws2812.c` |
| ไฟวิ่งผิดลำดับ | `WS2812_SERPENTINE`, `WS2812_FLIP_X/Y` |

### ขั้นที่ 3 — ไฟเส้นที่ 2–4
- ต่อทีละเส้น เพิ่ม DMA ใน CubeMX ทีละ channel แล้วขยาย mask (`0x03`, `0x07`, `0x0F`)
- ผ่านเมื่อ: ลาย "สีประจำ channel" = แผง 0 แดง, แผง 1 เขียว, แผง 2 น้ำเงิน, แผง 3 เหลือง
- ไม่ผ่าน: สีไปผิดแผง → แก้ `WS2812_CHANNEL_TO_PANEL`

### ขั้นที่ 4 — สวิตช์ทีละแผง
- ต่อ: คอลัมน์ 8 เส้น + แถว 7 เส้นของแผงนั้น (+ pull-up)
- ทำ: กด**ทุกปุ่ม** 56 ปุ่ม ทีละปุ่ม
- ผ่านเมื่อ: ไฟช่อง**เดียวกัน**กลายเป็นขาว (กดซ้ำ = ดับ), ช่องล่าสุดเป็นแดง, ตัวนับเพิ่มทีละ 1
| อาการ | แก้ |
|---|---|
| ปุ่มไม่ติด | ไดโอดกลับทิศ, สายแถว/คอลัมน์หลุด |
| ทั้งแถว/คอลัมน์ไม่ติด | สายเส้นนั้น, ชื่อขาใน CubeMX |
| ไฟติดผิดช่อง (กลับซ้าย-ขวา/บน-ล่าง) | `KEYPAD_FLIP_X/Y` (หรือ `WS2812_FLIP_*` ถ้าไฟเป็นฝ่ายผิด) |
| ไปติดแผงอื่น | `KEYPAD_GROUP_TO_PANEL` |
| กดครั้งเดียวนับ 2 | เพิ่ม `KEYPAD_DEBOUNCE_SCANS` |
- ทดสอบ ghosting: กดค้าง 3 ปุ่มเป็นรูปตัว L → ต้องไม่มีช่องที่ 4 ติดเอง
- ทดสอบพร้อมกัน: 2 คนกดแผงคนละฝั่งพร้อมกัน → ติดครบทั้งสอง

### ขั้นที่ 5 — Buzzer
- ผ่านเมื่อ: เปิดเครื่องมีเสียง START (ทั้งสองตัว), กดปุ่มแผงฝั่ง P1 → คลิกเฉพาะ buzzer P1
- ไม่ผ่าน: ไม่ดัง → ขา 2N2222, buzzer ต้องเป็นแบบ passive; ดังผิดฝั่ง → สลับสาย PC6/PC7

### ขั้นที่ 6 — สวิตช์ปิดเสียง
- ผ่านเมื่อ: เลื่อนแล้ว `MUTE:ON` ขึ้นทันที, กดปุ่มแผงแล้วฝั่งนั้นเงียบ อีกฝั่งยังดัง; ตัวเลขในวงเล็บเพิ่มทุกครั้งที่เลื่อน (= EXTI ทำงาน)
- ไม่ผ่าน: ON/OFF กลับกัน → สลับขาข้างของสวิตช์ หรือกลับเงื่อนไขใน `app.c`/`buzzer.c`

### ขั้นที่ 7 — สวิตช์ยอมแพ้
- ผ่านเมื่อ: กด 1 ครั้ง `SURR` +1 พอดี + เสียง SUNK ฝั่งนั้น
- ไม่ผ่าน: +2 ต่อครั้ง → เพิ่ม `SURRENDER_DEBOUNCE_MS`; ไม่เพิ่ม → NVIC EXTI15_10 ยังไม่เปิด

### ขั้นที่ 8 — LCD ×2
- ผ่านเมื่อ: จอ TFT แสดง `LCD1 27:OK`, `LCD2 26:OK`, บรรทัด I2C มี `27 26`; LCD แสดง `LCDn OK KEY…` / `MUTE:… SURR…`
| อาการ | แก้ |
|---|---|
| ไฟจอติด ไม่มีตัวอักษร | หมุน contrast หลังโมดูล |
| `MISSING` แต่ I2C เจอ 3F/3E | ชิป PCF8574**A** → แก้ `LCD_I2C_ADDR` |
| เจอแค่ 27 ตัวเดียว | ยังไม่ได้บัดกรี A0 ที่จอ P2 |
| I2C: NONE | SDA/SCL สลับ, ไม่มี GND ร่วม |

### ขั้นที่ 9 — จอ TFT ×2
- ผ่านเมื่อ: แถบสีเรียง **R G B W** จากซ้าย, `TOP LEFT` อยู่มุมซ้ายบน, เห็นกรอบขาวครบ 4 ด้าน, จอ P1 เขียน `TFT P1`
| อาการ | แก้ |
|---|---|
| จอขาวล้วน | RST/CS/DC ผิดขา, ไม่มีไฟ VCC |
| R กับ B สลับ | `TFT_MADCTL` สลับบิต BGR (0x48 ↔ 0x40) |
| ภาพกลับด้าน/หมุน | `TFT_MADCTL` (เช่น 0x88, 0x28, 0xE8) |
| ภาพเป็นจุดเพี้ยน | ลดความเร็ว SPI (prescaler 8/16), สายสั้นลง |
| ภาพขึ้นผิดจอ | สลับสาย CS/CS2 |

### ขั้นที่ 10 — Touch (calibrate)
1. แตะมุม**ซ้ายบน** จด `RAW x y` → แตะมุม**ขวาล่าง** จด `RAW x y`
2. ใส่ใน `app_config.h`: `TOUCH_RAW_X_MIN` = x ซ้าย, `X_MAX` = x ขวา, `Y_MIN` = y บน, `Y_MAX` = y ล่าง (ค่ามาก→น้อยได้ = กลับแกน)
3. ถ้าแตะซ้าย-ขวาแล้วค่าที่เปลี่ยนคือ y → ตั้ง `TOUCH_SWAP_XY` เป็น 1
4. ผ่านเมื่อ: เป้าแดงขึ้นใต้นิ้วทุกมุม คลาดไม่เกิน ~5 px · แตะ 1 ครั้งนับ +1 (ไม่ใช่ +2)

### ขั้นที่ 11 — เล่นเกมจริง (`APP_HW_TEST 0`)
| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| 1 | เปิดเครื่อง | TFT P1 = Home, P2 = WAITING, LCD `SELECT MODE`, ไฟดับ |
| 2 | P1 แตะ 2. TWO PLAYERS | ทั้งสองจอเป็น Select Ships, แผงเรือเป็นน้ำเงิน |
